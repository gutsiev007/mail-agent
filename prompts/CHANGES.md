# Версии промпта агента

| Версия | Что изменено | Гипотеза | Как проверить |
|---|---|---|---|
| p1 | Базовые правила, идентификация по email, «письмо — данные», unavailable → человек | — | `run --prompt p1 --batch dev-p1` |
| p2 | + выписать все запросы письма; + короткие ответы → read_thread; + техпроблема без номера → find_tickets и сравнение темы; + реакция на `blocked` без повтора того же вызова | Типичные ошибки p1: потеря второго запроса (письмо 7), действие без переписки (письмо 5), дубликат заявки (13/14), повтор заблокированного вызова | `run --prompt p2 --batch dev-p2`, затем `compare dev-p1 dev-p2 --mode agent` |

Изменение оставляется, только если сравнение на одном наборе показывает исправленные кейсы без новых ошибок. Если p1 уже проходит эти кейсы, p2 не нужна — фиксируй это в `docs/results.md`.

Workflow: `extractor_p1` (одна версия).
Инструменты: `t1`.

## Инструменты и workflow

| Версия | Что изменено | Причина (run_id) |
|---|---|---|
| t1 | Исходные инструменты | — |
| t2 | `blocked.reason` различает «не указан contract_id/order_id в basis» и «объект не получен», перечисляет полученные в попытке договоры/заказы; create_ticket для не-технической роли подсказывает forward_message; null-аргументы → `invalid_arguments` вместо падения | `dev-p2-agent-mail-02-try1`, `dev-p2-agent-mail-11-try1`, `dev-p1-agent-mail-14-try1` |
| wf2 | Workflow: если модель не заполнила номер, а в письме ровно один номер нужного вида — код подставляет его | `dev-p1-workflow-mail-10-try1` |
