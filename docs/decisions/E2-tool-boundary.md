# E2. Граница инструментов

**До.** `Toolbox.call` ловил `TypeError/AttributeError` и отдавал модели текст исключения: `get_order(order_id=52)` → `'int' object has no attribute 'strip'`. Настоящий баг выглядел так же. `KeyError` обрывал попытку.

**Выбор: A.** Свой мини-валидатор (около 30 строк) проверяет аргументы по уже объявленным JSON-схемам: тип, обязательные поля, enum, неизвестные поля (`additionalProperties: false`). Ошибка аргумента → `{"status": "invalid_arguments", "code": "invalid_arguments", "message": "...", "errors": [...]}` без имён Python. Любое исключение внутри инструмента → `{"status": "error", "code": "internal_error"}`, событие `internal_error` с traceback в трассе, отдельный счётчик в отчёте. Попытка завершается, письмо передаётся человеку.

**Почему без библиотеки.** Первая внешняя зависимость ради пяти схем не окупается: проект запускается одной командой на любом Python 3.10+.

**Коды ошибок** теперь отдельным полем `code`, текст для модели — в `message`.

**Цена.** Схемы и валидатор надо поддерживать вместе: новое ключевое слово схемы валидатор не поймёт.

**Тест.** `ToolBoundaryTest`: неверные типы, строка вместо объекта, лишнее поле → контролируемый отказ; повреждённые данные (`KeyError`) → `internal_error`, счётчик, передача человеку.
