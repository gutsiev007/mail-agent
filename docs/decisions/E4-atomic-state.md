# E4. Хранилище состояния выдерживает обрыв записи

**Выбор: A.** `atomic_write`: запись во временный файл → `fsync` → `os.replace`. Файл состояния всегда либо старый целый, либо новый целый. Повреждённый файл (запись другой программой или вручную) даёт `StateCorrupted` с понятным текстом, без молчаливого «начать с нуля».

**Что нельзя терять и дублировать.** И пересылку, и заявку. Обе защищены одинаково: эффект и ключ идемпотентности пишутся одной записью файла.

**Возобновление.** `--resume` пропускает попытки, уже записанные в `results.jsonl` с любым статусом, кроме `infra_error`; упавшие запускаются заново с новым `run_id` (суффикс `-r<время>`), отчёт берёт последнюю запись на попытку. Каждая попытка пишет свой файл состояния, поэтому повтор не трогает чужие эффекты.

**Цена.** Файл переписывается целиком при каждом эффекте, истории изменений нет. Защиты от двух процессов одновременно нет: стенд запускается одним процессом.

**Тест.** `StorageTest` (обрыв `os.replace` → старое состояние цело; повреждённый файл → понятная ошибка), `InfraTest` (`--resume` не дублирует).
