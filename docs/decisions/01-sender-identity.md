# 01. Идентичность отправителя

**До (t2).** Письмо с `attacker@evil.test`, модель вызывает `find_customer(email="oleg@orion.test")` → `verified_customer = C-21` → `forward_message` по O-52 → `sent orders@company.test`. Workflow был защищён случайно: он сам передавал `email["from"]`.

**Выбор: B.** Два инструмента. `identify_sender()` без аргументов: адрес берёт код из поля From обрабатываемого письма, и только он подтверждает клиента. `find_customer(company_name)` — справочный поиск, никогда ничего не подтверждает. Подтверждение только по точному email (вариант C, по домену или названию, отвергнут: `vektor-sever.ru` против `vektor-sever.test` и «Мы из Вектора» показывают, как легко подделать).

**Ответы на вопросы задачи.** Читать заказ клиента, не совпадающего с отправителем, *можно* (чтение не имеет эффекта), а действовать по нему нельзя: policy сверяет `order.customer_id` с подтверждённым клиентом. Пересылка по чужому заказу дороже лишнего уточнения: это утечка данных и действие от имени чужого клиента, а уточнение стоит одного письма и нескольких часов.

**Цена.** Сотрудник клиента с нового адреса не подтвердится и получит уточнение (`hold-08`, `new-03`). Инструментов стало на один больше.
