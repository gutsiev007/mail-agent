# E1. Сбой стенда не должен выглядеть как ошибка модели

**До.** В `dev-p1` 21 из 45 попыток агента упали с `Connection refused` и посчитаны неверными. Батч не остановился. На 8 письмах, где обе версии реально выполнились, p1 дал **21/24**, p2 — **11/24**. Утверждение «p2 лучше» не подтверждается данными и **отозвано**; основа новой версии — p1 (промпт p3).

**Выбор: A + B.**
- Перед батчем `preflight`: один короткий вызов каждой модели. Сервер не отвечает, ключа нет или модель не найдена — батч не начинается.
- Любая `LLMError` (сеть, HTTP, не-JSON, неожиданная структура) даёт статус `infra_error`. Такие попытки **исключаются из знаменателя** всех метрик и показываются отдельной строкой отчёта.
- Три `infra_error` подряд останавливают батч с понятным сообщением.
- Автоповтора нет: упавшие попытки повторяет `--resume` (решение E4), завершённые не дублируются.

**Таймаут.** Срок попытки (`max_seconds`) — это решение о модели (слишком медленно), статус `time_limit`, остаётся в знаменателе. Сетевой таймаут отдельного запроса — `infra_error`.

**Цена.** Если сервер падает только на «трудных» письмах, исключение из знаменателя скроет это. Поэтому отчёт перечисляет письма с `infra_error`.

**Тест.** `InfraTest`: недоступная модель → батч остановлен после 3 попыток, `correct` нигде нет, отчёт показывает сбои отдельно, `--resume` повторяет только упавшие.
