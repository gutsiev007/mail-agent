## Два развития событий

**Письмо 2 (доставка):**
- O-52 `paid / not_shipped` → `forward(order_operations)`.
- O-52 `paid / handed_to_carrier` → `forward(logistics)`. Кейс `mail-02-shipped` проверяет это изменением одного факта в стенде.
- `get_order` недоступен → не угадывать, `escalate_to_human` (кейс `mail-09`); временный сбой → повтор кодом (`mail-10`).

**Письмо 1 (техпроблема и договор):**
- Договор закончился → `forward(contract_manager)`, обещать обслуживание нельзя.
- Договор действует и расширенный → `create_ticket(engineers_group)` (кейс `mail-11`); обычный → `create_ticket(support_general)` (`mail-12`).
- У клиента уже есть открытая заявка на ту же тему → дополнить её (`mail-13`), на другую тему — новая обработка (`mail-14`).

## Решение для первой версии

- **Категории запроса** (внутренние, для workflow): `order_status`, `technical_issue`, `ticket_continuation`, `purchase`, `other`. Отдельных категорий «техпроблема + истёкший договор» нет — это решают факты, а не категория.
- **Действия:** пересылка по роли, новая заявка, дополнение заявки, уточнение отправителю, передача человеку.
- **Вне первой версии:** изменение заказов/оплаты, ответы клиенту по существу, поиск в интернете, удаление писем.
- **Путь к человеку:** неопознанный отправитель, неоднозначный предмет, недоступный источник, инструкции в письме, неоплаченный заказ, нет договора.
