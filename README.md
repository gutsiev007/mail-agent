# Агент для входящей почты сервисной компании

Учебный проект: агент (модель выбирает следующий шаг) и workflow (шаги заданы кодом) на **общих** данных, инструментах и исполнении действий. Всё работает на локальном стенде: отправки — в локальный outbox, адреса в доменах `.test`.

## Запуск

Нужен только Python 3.10+ (внешних зависимостей нет).

```bash
cd mail-agent
python -m unittest discover -s tests -v      # проверка стенда, правил и оценки без API
python -m mailagent validate                  # проверка файлов писем

# Anthropic
export ANTHROPIC_API_KEY=...                  # Windows: set ANTHROPIC_API_KEY=...
python -m mailagent run --mode both --set dev --trials 3 --prompt p1 --batch dev-p1

# или любой OpenAI-совместимый (OpenRouter, DeepSeek, локальная Ollama)
python -m mailagent run --mode both --set dev --config config/models.local.json --batch dev-local   # Ollama + qwen2.5:7b-instruct
```

Один сценарий и его проверка:

```bash
python -m mailagent run --mode agent --cases mail-01 --batch demo1
python -m mailagent show demo1-agent-mail-01-try1      # все обращения к модели и инструментам
python -m mailagent effects demo1-agent-mail-01-try1   # созданная пересылка/заявка на стенде
```

Результаты: `runs/<batch>/trace.jsonl` (трасса), `results.jsonl` (оценка каждой попытки), `state/<run_id>.json` (состояние стенда), `report.md` (таблицы). Старые запуски не перезаписываются.

## Модели

| Роль | Модель | Параметры | Почему |
|---|---|---|---|
| Агент и разбор письма в workflow (**основные прогоны**) | `qwen2.5:7b-instruct` через Ollama, локально | агент: temperature 0.2, max_tokens 1024; разбор: temperature 0, max_tokens 800; лимит агента 10 шагов / 300 с | Бесплатно и без ограничений запросов. **Одна модель в обоих режимах**, поэтому разница режимов связана с архитектурой |
| Альтернатива: Claude через OpenRouter | агент `anthropic/claude-sonnet-4.6`, разбор `anthropic/claude-haiku-4.5` | `config/models.openrouter.json` | Пробный запуск `mail-02` прошёл правильно в обоих режимах; полный прогон не выполнен из-за бюджета |

Конфигурации — `config/*.json`, ключи только в переменных окружения. Фактическая модель записывается в каждый `llm_call` трассы.

## Итог в двух строках

Workflow — **39/45** на разработческих и **15/15** на новых письмах, агент — 33/45 и 9/15 при той же модели, в 25 раз больше токенов и в 5 раз медленнее. Оставляю **workflow с одним узким шагом выбора моделью** (та же ли это проблема, что в открытой заявке). Подробно в [docs/results.md](docs/results.md), к защите — [docs/defense.md](docs/defense.md).

## Что проверено без API (тесты)

Тесты подставляют заранее заданные ответы модели и проверяют инфраструктуру, а не качество модели:
- чтение: найдено / не найдено / недоступно / временный сбой с повтором;
- имя компании не подтверждает отправителя (два «Вектора»);
- policy блокирует: неподтверждённого отправителя, ненаблюдённый заказ, неверную роль; повтор пересылки → `duplicate`;
- потерянное подтверждение и перезапуск — без второй отправки;
- **workflow на всех 15 письмах при идеальном разборе: 14/15** — ошибается на `mail-14` (правило «одна открытая заявка = продолжение» дописывает новую тему в T-9). Это ограничение логики, не модели;
- агентный цикл: два действия в письме 7, блокировка инъекции, остановка по лимиту шагов.

Сравнение агента и workflow, исправленная ошибка и выбор архитектуры — по реальным прогонам в `docs/results.md`. Все попытки сохранены в `runs/` (`dev-p1`, `dev-p2`, `new-final` — до исправлений; `dev-v2`, `new-v2` — после).
